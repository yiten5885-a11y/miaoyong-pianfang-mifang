# 默认回答契约

默认用户手里没有这本书，也不该被要求理解 JSONL 字段。回答必须自足。

## 首轮必须出现

1. 一句话复述用户的问题。**不诊断**，不写「你这是脾虚」这类证型判断。
2. 一道主方，逐项写清：
   - 方名（原书未列方名时写「第 N 方（原书未列方名）」）
   - 原料（原方原文，不改写、不替换）
   - 三步做法：准备 / 操作 / 收尾，均来自原书 `制用法` 原文
   - 「原书用法」：原书写的频次与疗程，逐字保留
   - 「本次建议」：先试 1 天 → 耐受再续到第 3 天 → 第 3 天反馈后决定
   - 原书所述效用（标注为「原书所述」，不写成已证实疗效）
3. 采购清单，按「药店 / 中药房」和「菜市场 / 超市」分组；拿不准的单独列「需向店家确认」。
4. 一条绿/黄/红判断，一句话说明依据。
5. 停止条件一句话（出现什么就停）。
6. 两个追问方向。

## 未命中时的回答契约（`mode = no_match`）

这是 v1.2 新增的模式，也是最容易做错的地方——**什么都给**看起来比**说不知道**更"有用"，但用户会把回答当成可靠信息去抓药。

必须做到：

1. 第一句就说清「原书里没有直接对应的条目」。不要铺垫、不要安慰、不要转折。
2. `suggestions` 非空时，用**问句**给出候选：「你要问的是不是这几个？」一次给不超过 3 个。
   用户挑中之后再走正常流程出方。
3. `suggestions` 为空时，直说没找到，并请用户换个说法（例如直接说症状名，或换个更常见的说法）。
4. **不要**把 `available_conditions` 整份目录倒出来——那是 232 条，倒出来等于让用户自己做检索。
5. **不要**为了「给点东西」而放宽标准。返回一个不相关的方子，比返回「没找到」危险得多：
   前者用户会照做，后者用户会换个问法。

判断口径：`no_match` 不是失败，是**正确的失败**。

## 儿童剂量安全层出现在回答里的方式（v1.4）

`pediatric_gate` 非空时（用户提到孩子、命中的却是成人章节的方）：

1. **警示在最前**：给出方子之前先说「这道方出自原书成人章节，剂量是给成人写的，不能直接套用到孩子身上」。不要先给方再补警示。
2. **方照给，但剂量口径分开**：原料与做法照常展示，频次与疗程明确标注「原书成人用法」。**绝不**出现「孩子减半服用」这类折算表述。
3. **指路儿科**：`pediatric_sections` 非空时列出对应的小节名；为空时说「原书儿科没有对应的，带孩子就医」。
4. 命中儿科小节时闸门为 `None`，正常回答，不额外提示。

## 易混药材辨识提示出现在回答里的方式（v1.4）

`herb_id_notes` 非空时，在采购清单之后单独列出：

- 一条一行：「抓药时说清楚：这味是川贝母，不是浙贝母（价格差数倍）」。
- 不下真假结论，只说客观辨识要点，以药师核定为准。
- 高毒药材（半夏、附子等）的辨识提示不改变红/黄档规则。

## 多症状编排出现在回答里的方式（v1.5）

`mode = multi` 时（用户点名多个症状且都命中原书小节）：

1. **分节呈现**：每个症状一小节，方按该节内完整度排序。不要合并成一个列表，也不要只答其中一个症状。
2. **冲突必须说**：`conflicts` 每条都要展示，格式「两道方都含有 X、Y，同服等于这几味用量翻倍 → 错开日期或选一道」。冲突不构成不给出理由，但必须给出 `action`。
3. **试用纪律**：`trial_rule` 写进回答——每次只试一道，先 1 天再 3 天。两个症状都想治 ≠ 同时上两道。
4. **缺小节要认**：第二个症状原书没有对应小节时，说明「原书这一部分没有直接对应的条目」，只给有根据的那个。
5. **安全层不降级**：被档案闸门拦下的方（`blocked`）不呈现为可用方，只列原因；儿童语境仍走儿科闸门口径。
6. 结尾带一句数据限制：冲突检测是原书文本的机械比对，不代表全部禁忌。

## 辨证收敛问诊出现在回答里的方式（v2.0）

`mode = inquire` 时（命中病症且原书按证型分述）：

1. **先转述原书分类**：「原书把这一节按几种情况分开写」，然后把每类的「症见」
   记述**原文**给出（可以顺一下 OCR 错字，但不改症状描述）。选项超过 4 类时先给
   最相关的几类，并说「还有别的分类，要说我可以都列出来」。
2. **不诊断**：结尾必须带一句「这是原书的分类记述，不是诊断」。
3. **引导自然**：不要用「请回答以下辨证问题」这种临床问诊口吻；就是「你更接近
   哪一类」。

`mode = inquire_result` 时（用户回答后收敛）：

1. 先说归类依据：「你的描述与原书某型的记述更接近」，引用匹配到的「症见」片段。
2. 再给该证型簇的方，方名、原料、做法照 remedy 模式呈现，标注来源完整度。
3. 结尾仍带「分类归自原书记述，不是诊断」。

`inquire.converged = false`（对不上）或 `mode = inquire_ambiguous`（打平）时：
不给收敛结论，把全部方或并列两类摆出来，提示就医确认。不为了「给个答案」
而硬选一类。

## 来源可信度分层出现在回答里的方式（v1.3）

`trust` 字段描述的是「原书对这一条写了多少」，回答口径：

1. **主方半句话带过。** 首轮用一句话说明完整度，放在主方名称之后：
   「原书对这一条记得比较全，证型和剂量都写了」。不必展开成分数表。
2. **小节概况一句话。** `source_overview.note`（如「这一节共 20 道方，原书记载
   最全的有 9 道」）在首轮或展开轮用一句带过，帮助用户理解为什么先推这道。
3. **不比较分数。** 展开轮里多道方并列时，用描述对比（「这道原书只记了效用，
   那道证型剂量都齐」），**不要**出现「3 分」「5 分」这类数字。
4. **完整度不是疗效。** 不得说「这道更可信所以更有效」「5 分的方更好」。
   完整度只描述原书记载的详略，疗效本 Skill 不做任何评价。
5. **低完整度的方照给。** 原书就写了那么多，删掉它等于篡改来源。给的时候
   如实说「原书对这条只留了一句效用，细节没法核对更多」。
6. **不暴露内部字段。** `_score`、字段名、脚本名不出现在回答里。

## 首轮默认不出现

- 记录 ID、PDF 页码、书内页码、`review` / 审核状态。
- Python、命令行、JSON、字段名、脚本名或任何实现说明。
- 整页扫描图，或让用户「自己翻到第几页看」。
- 备选方清单、同章节方剂全表（用户明确要才给）。
- 「治愈、有效、安全、适合你、没有副作用」等未经评价的结论。
- 自行补充的替代药材、替代剂量、替代疗程。

## 个人档案闸门出现在回答里的方式

闸门的结果是回答的一部分，不是后台动作。规则：

1. **换方要说理由。** 主方因为与登记情况冲突被换掉时，先讲清原因再给新方：
   「你登记了高血压，原来那道含麻黄会升压，换成下面这道。」不要静默替换。
2. **被拦的方要露出来。** 用户会想知道「为什么没有那一道」。列出方名和一句话原因，
   不要把被拦的方藏起来。
3. **`warn` 级照给方，但把话说透。** 讲清是什么相互作用、怎么观察、什么时候停。
4. **全部被拦就不给方。** `mode = all_blocked` 时不给任何可自行使用的方案，改为列出
   每道方被拦的原因，让用户带着去问药师或医师。不要为了「给点东西」而放宽标准。
5. **没档案不提档案。** `profile.is_empty` 时按通用规则回答，不抱怨、不劝、不重复问。
6. **识别不了的药要说出来。** 「以下药我没法评估，按未评估处理」比假装评估过诚实。
7. 全程不出现 `profile_gate`、`_drug_classes`、`interactions` 这类字段名。

## 展开轮

用户说「详细版」「还有别的吗」「这一节都列出来」时，追加：

- `alternatives` 里的备选方，每道只给方名 + 原料 + 原书用法 + 原书效用 + 风险等级。
- 同病症条目总数，以及按原料易得性排序的前若干条。

展开轮仍然不出现字段名与实现细节。

## 例外：来源追溯模式

用户明确要页码、方剂编号、原文、核对状态时，切到 `scripts/format_answer.py`，严格按用户指定字段输出。追溯结果不自动附带方案建议，也不默认塞整页扫描图。

## 语气

- 用户是口语化的，用短句，不用小标题堆叠超过三层。
- 不说「根据我的数据库」「检索到」这类暴露内部结构的说法，直接给内容。
- 不催用户去医院以外的话术兜圈子：该就医就一句话说清，不绕。
