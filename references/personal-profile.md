# 个人用药档案与相互作用闸门

这是 v1.1 的核心变化：**回答不再对所有人一视同仁，而是先过一遍你自己登记的情况。**

在此之前，`references/toxic-herbs.md` 能回答「这道方本身危不危险」；现在还能回答
「**这道方对你危不危险**」。两者是不同的问题，需要不同的数据。

## 为什么需要它

实测原书 2395 条记录里，**只有 16 条（1%）写了禁忌**。也就是说，安全信息几乎全部
要靠本 Skill 自建。而「通用警告」的问题在于：给所有人看同一句「高血压者慎用麻黄」，
用户看三次就麻木了。

档案把通用警告变成**针对个人的拦截**：

| 之前 | 现在 |
| --- | --- |
| 「含麻黄的方，高血压者慎用」 | 「你登记了高血压，这道含麻黄，已自动跳过，改用下面这道」 |
| 每轮都要重新问一遍你的情况 | 问一次，之后每轮自动生效 |
| 过敏史靠用户自己记得 | 登记的过敏原命中即拦截，不看给药途径 |

## 档案长什么样

存在本机，默认路径：

```text
~/.miaoyong-pianfang-mifang/profile.json
```

可用环境变量 `MIAOYONG_PROFILE_PATH` 改到别处。文件权限固定为 `0600`（仅本人可读写）。

```json
{
  "version": 1,
  "updated_at": "2026-10-15T16:40:12+00:00",
  "conditions": ["高血压", "2型糖尿病"],
  "medications": ["氨氯地平", "二甲双胍"],
  "allergies": ["蜂蜜"],
  "special": ["老年"],
  "diet": ["低盐"],
  "notes": ""
}
```

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `conditions` | 慢性病 / 已知疾病 | 高血压、糖尿病、肝病、肾病、胃溃疡、蚕豆病 |
| `medications` | 长期服用的西药 | 氨氯地平、华法林、二甲双胍 |
| `allergies` | 食物或药物过敏 | 蜂蜜、蚕豆、某种药材 |
| `special` | 特殊状态 | 孕期、备孕、哺乳、婴幼儿、儿童、老年 |
| `diet` | 饮食限制 | 低盐、限糖、低嘌呤 |

## 隐私边界（重要）

- **只存本机。** 本 Skill 包内所有脚本都不发起网络请求，档案不会被上传。
- **完全可选。** 不建档案时闸门处于惰性状态，回答与 v1.0 一致，不会因为「猜你有病」而误拦。
- **随时可删。** 一条命令清除，无残留：

  ```bash
  python3 scripts/profile.py --clear
  ```

- **不推断。** 闸门只匹配你自己写下的字。你没说高血压，它就绝不会按高血压拦。
- 档案文件是纯文本，你可以直接用编辑器打开检查或修改。

## 怎么设置

助手会在第一次给出方案前问几个问题，然后写档。也可以自己敲命令：

```bash
# 一次性设置（会覆盖同名字段）
python3 scripts/profile.py \
  --conditions "高血压,2型糖尿病" \
  --medications "氨氯地平,二甲双胍" \
  --allergies "蜂蜜" \
  --special "老年" \
  --diet "低盐"

# 追加
python3 scripts/profile.py --mode add --conditions "脂肪肝"

# 删除某一项
python3 scripts/profile.py --mode remove --medications "二甲双胍"

# 查看当前档案
python3 scripts/profile.py --show

# 查看档案文件位置
python3 scripts/profile.py --path

# 清空
python3 scripts/profile.py --clear
```

助手侧也可以直接传一段 JSON：

```bash
python3 scripts/improve.py --issue "老咳嗽" \
  --profile-json '{"conditions":["高血压"],"medications":["氨氯地平"]}'
```

`--profile-json` 只在本次生效，**不写盘**。`--no-profile` 则完全忽略本地档案。

## 闸门怎么工作

对每一个候选方（主选 + 备选）执行三步：

1. **算给药途径。** 从原书【制用法】判断是内服还是外用。原书把内服方和外用方混在
   同一节里，`麻黄外用治疗风寒咳嗽` 是贴在肺俞穴的膏药，不是汤剂。两者按同一标准
   处理在两个方向上都错：既会拦掉安全的外用方，也会低估内服方的风险。
2. **匹配规则。** 每条规则同时要求「方里含有指定药材」**且**「档案命中指定条件」。
   任何一侧单独出现都不触发——只有药材不会拦，只有病史也不会拦。
3. **定级。**
   - `block`（红）：**换方**。命中的方从候选里剔除，自动改用下一道未冲突的方。
   - `warn`（黄）：**保留但明说**。方照给，把相互作用讲清楚，并给出观察要点。
   - 外用方：命中 `block` 级规则时降一级为 `warn`，并附说明（全身吸收远低于口服）。

**拦截不会被静默丢弃。** 被换掉的方会连同原因一起出现在回答里，用户能看到
「为什么这道被跳过了」，而不是凭空少了一道。

如果这一节里所有能匹配到的方都被拦下，返回 `mode = all_blocked`，不给方案，
改为列出每道方被拦的原因和建议动作，让用户带着这些去问药师或医师。

## 规则表覆盖范围

规则定义在 `scripts/interactions.py` 的 `INTERACTION_RULES`。目前覆盖：

**药材 × 西药**

- 麻黄 × 降压药 / 单胺氧化酶抑制剂 / 强心苷
- 甘草 × 利尿剂 / 强心苷 / 保钾类药物 / 降压药 / 糖皮质激素
- 活血化瘀类（丹参、当归、川芎、红花、桃仁、水蛭、三七…）× 抗凝与抗血小板药
- 人参 / 黄芪 × 降糖药 / 抗凝药
- 黄连、黄芩、黄柏、大黄、丹参 × 华法林
- 五味子 × 他克莫司 / 环孢素
- 含钙药材（石膏、牡蛎、龙骨…）× 四环素 / 喹诺酮类
- 海藻、昆布 × 甲状腺用药
- 洋金花、曼陀罗、天仙子 × 抗胆碱能药
- 含酒辅料 × 甲硝唑 / 头孢 / 降糖药 / 镇静药 / 他汀
- 乌头类 × 心脏用药

**药材 × 疾病**

- 麻黄 × 高血压 / 心脏病 / 甲亢 / 失眠 / 前列腺增生
- 甘草 × 心衰 / 高血压 / 肾病
- 活血化瘀类 × 出血倾向 / 血小板减少 / 崩漏
- 泻下类 × 胃溃疡 / 胃炎 / 肠炎
- 马兜铃酸类 × 肾病
- 含糖辅料 × 糖尿病
- 蚕豆及氧化性药材 × 蚕豆病

**特殊状态**

- 孕期 / 备孕 × 活血化瘀、峻下逐水、乌头与半夏南星、含酒
- 哺乳期 × 泻下类、麦芽、薄荷
- 婴幼儿 × 蜂蜜、含酒
- 老年 × 峻下类

**饮食限制**

- 限盐 × 含盐调味

## 药物识别

档案里的西药名按**子串匹配**映射到药物类别，商品名和通用名都能识别
（`氨氯地平`、`降压药` 都归入 `antihypertensive`）。

**识别不了的药会明确列出来，按「未评估」处理，不会猜。** 回答里会提示：

> 注意：以下药物未在相互作用库中登记，按未评估处理：×××

这是刻意的保守设计——宁可告诉你「这个我没法评估」，也不假装评估过了。

## 能力边界

- **不是药物相互作用数据库。** 规则表是保守的经验集合，覆盖的是最常见、后果最重的
  组合。未命中的组合不等于安全。
- **不能替代药师。** 所有 `block` 级规则的动作都指向「换方」或「咨询医师／药师」，
  本 Skill 不做剂量调整、不做替代用药建议。
- **不做诊断。** 触发条件只匹配用户自己写下的字，不推断未声明的疾病。
- **规则表可以扩充。** 新增规则后跑一遍 `python3 -m unittest discover -s tests`，
  测试会校验规则表的完整性（每条规则必须有药材、触发条件、原因和动作）。
